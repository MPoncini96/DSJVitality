# School Vitality: independent prototype

A dashboard of operational health (enrollment, finance, facilities, data quality) for Catholic elementary schools in Santa Clara County, built as a portfolio piece.

> **Independent prototype by Matthew Poncini. Not affiliated with or endorsed by the Diocese of San José.**
> The 25 real schools show public data only. Internal data (budgets, facilities, admissions, the Turnaround Program) is simulated and belongs to 25 fictional demo schools, School A–Y. See `data/SOURCES.md`.

## Setup

```bash
npm install
npm run data      # schools, CDE enrollment, CDPH births, published tuition, then the demo system in data/sample/
npm run dev       # http://localhost:3000
npm test          # Vitest
npm run build
```

## Pages

- **Radar** (`/`): the 25 parish schools (enrollment, scenario range, published tuition, the top five to look at first, the calendar, the enrollment trend and the school table), then a separate demo section with the Enrollment & Finance Matrix, Turnaround check-ins and composite health for the fictional schools.
- **Alerts** (`/alerts`): enrollment items for the real schools; `/alerts?view=demo` shows every area for the demo schools.
- **Turnaround Program** (`/turnaround`): the process, roster, flagged schools and action plans, all on demo schools.
- **School page** (`/schools/[id]`): a real school, public data only: Overview, Enrollment (with scenarios), Tuition, Data quality.
- **Demo school page** (`/demo/schools/[id]`) and **Demo schools** (`/demo`): how a school page looks with internal data.
- **About the data** (`/about`) and **Why I built this** (`/about-me`).

## The two systems

- Real schools (`data/schools.csv`) carry only REAL rows: CDE enrollment and staffing, CDPH births, published tuition.
- Demo schools (`data/sample/demo_schools.csv`, ids `demo-a`..`demo-y`) carry only SAMPLE rows, generated by `scripts/generate_sample.ts` from generic ranges (fixed seed). Nothing in the generator reads a real school's figures; it reads only the latest school year, so both systems share one reference year.
- `lib/data.ts` refuses to load a SAMPLE row for a real school or a REAL row for a demo school.
- `lib/names.ts` `displayName(school, context)` returns a real name only in a REAL context and throws otherwise.

## Scores and alerts

- `lib/metrics.ts` computes each school's numbers. The long trend runs from 2019-20 (`BASE_YEAR` in `lib/config.ts`), labeled "since 2019-20".
- **Enrollment Vitality** (`lib/health.ts`) is the only score a real school gets. The **Composite** (Vitality 50%, Financial 35%, Facilities 15%) exists only for demo schools.
- **Scenarios**: a low–high range from two what-ifs (the capped trend since 2019-20, and the local births curve). Labeled "Scenario, not a forecast"; never used in alerts.
- `lib/radar.ts` holds the alert rules. Critical: trend ≤ −6%/yr or a one-year drop ≥ 12%. Serious: 3+ straight declines and trend ≤ −4.5%/yr. Everything else is a watch item.
- Dates: the latest school year comes from the CDE data; other constants live in `lib/config.ts`. The calendar and check-ins compare with today's date in the browser.

## Data refresh

```bash
pip install requests openpyxl
python scripts/fetch_cde_enrollment.py --out data/raw/cde_enrollment_$(date +%F).json
npm run data
```

The import stops with a list of problems if any value fails validation. Review `data/match_review.csv` after each refresh.

## Checks

`npm test` covers the data rules. `scripts/audit_pages.mjs`, a rendered-HTML audit (Playwright), checks every page at 1280px and 375px for: a real school name inside a simulated card, more than one health band on a real school page, a past date under "Coming up", a projection in alert text, and horizontal scroll.

## Presentation rules

- Real cards render normally with their source cited. Simulated cards are hatched with one small "Simulated" tag. Scenarios and third-party tuition carry a short italic note.
- No logos, seals or diocesan branding. No API keys in the repo.
